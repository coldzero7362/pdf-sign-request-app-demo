# 업무 지침

- 버전: v1 (2026-11-23)
- **이 문서가 현재 구현보다 우선합니다.** 구현이 지침과 다르면 지침에 맞춰 고칩니다.
- **수정 규칙**: 사용자가 "지침 업데이트"를 지시할 때만 고칩니다. 지침에 없는 내용을 임의로 정하지 않습니다. 해석이 필요하면 아래 "미정 사항"에 적고 사용자에게 묻습니다.

## 용어

| 용어 | 뜻 |
|---|---|
| 요청자 | 서비스에 로그인해 템플릿을 만들고, API로 서명을 요청하는 사람 |
| 서명자 | 서명 요청을 받아 문서에 서명하는 사람 (계정 없음) |
| 참조자 | 서명이 모두 끝난 문서만 받는 사람 |
| 템플릿 | 서명 요청에 쓰는 문서 양식. 요청자가 웹에서 만들고 편집한다 |
| 문서 | 템플릿으로 만든 서명 요청 한 건 |
| 종료처리 | 문서가 더 이상 진행되지 않는 상태가 되는 것 (반려, 회수 등) |

## 지침

### 1. 요청자 웹 화면
요청자가 웹 페이지에서 할 수 있는 일은 다음뿐입니다.
- 보낸 문서 관리
- 템플릿 관리, 템플릿 생성·편집
- API 토큰 관리

### 2. 서명자 웹 화면
서명자는 웹 페이지에서 **전달받은 문서의 서명 진행만** 할 수 있습니다.

### 3. 참조자
참조자는 **서명이 끝난 뒤 문서만 메일로** 전달받습니다.

### 4. 서명 요청은 API로만
- 서명 요청은 **API 호출로만** 합니다. 웹 화면에서는 서명을 요청하지 않습니다.
- 요청 JSON에 **템플릿 번호**를 넣고, 해당 템플릿으로 서명을 요청합니다.

### 5. 반려
- 서명자는 받은 문서를 반려할 수 있습니다.
- 반려된 문서는 **후순위 서명자와 관계없이 즉시 종료처리**됩니다.

### 6. 회수
- 요청자는 **종료처리되지 않은 문서**를 **서명 요청 기간 안에** 회수할 수 있습니다.
- 회수된 문서는 종료처리됩니다.

### 7. 수정 후 재발송 API
회수되거나 반려된 문서의 **데이터를 수정해서 재발송하는 API**를 구현해야 합니다.

### 8. 그 밖의 사항
그 밖의 사항은 이후 결정하며, 사용자가 지침 업데이트를 지시할 때 이 문서에 반영합니다.

## 미정 사항 (결정 전에는 임의로 구현하지 않고 사용자에게 확인)

1. **서명 순서**: 지침 5의 "후순위 서명자"로 보아 서명자에게 순서가 있는 것으로 보입니다. 앞 사람이 끝나야 다음 사람에게 가는 순차 방식인지, 동시 진행도 허용하는지.
2. **템플릿 구성**: 템플릿에 무엇이 들어가는지 (PDF, 입력 칸, 서명자 자리(역할), 참조자 자리 등).
3. **요청 JSON 형식**: 템플릿 번호 외에 서명자·참조자 정보를 어떻게 넣는지. 템플릿의 서명자 자리와 어떻게 연결하는지.
4. **템플릿 번호 형식**: 숫자 번호인지, 다른 식별자인지.
5. **요청 데이터**: 지침 7의 "데이터"가 무엇인지 (서명자·참조자 정보, 기간, 문서에 미리 채우는 값 등).
6. **서명 요청 기간**: 요청할 때 API로 정하는지, 템플릿 기본값이 있는지, 최대 기간이 있는지.
7. **참조자 전달 방식**: 완료 PDF를 메일에 첨부하는지, 내려받기 링크를 보내는지.
8. **재발송 결과**: 같은 문서를 다시 진행하는지, 새 문서를 만드는지. 이전 서명은 어떻게 되는지.
9. **보낸 문서 관리 범위**: 웹에서 할 수 있는 동작 (조회, 회수, 완료본 내려받기 등). 회수를 웹에서도 할 수 있는지, API로만 하는지.
10. **서명자 본인 확인**: 지금처럼 메일 링크 + 이메일 인증번호를 유지하는지.

## 참고: 지침과 현재 구현의 차이 (2026-11-23 기준, 지침 아님)

| 항목 | 현재 구현 | 지침 |
|---|---|---|
| 서명 요청 | 웹에서 PDF 업로드 → 칸 배치 → 발송. API로도 같은 흐름 | API로만, 템플릿 번호로 요청 (4) |
| 템플릿 | 없음. 요청마다 PDF와 칸을 새로 만듦 | 웹에서 템플릿 생성·편집·관리 (1) |
| 요청자 웹 | 요청 작성, 편집, 발송까지 가능 | 보낸 문서 관리, 템플릿, API 토큰만 (1) |
| 서명 순서 | 모든 서명자가 동시에 진행 | 순서가 있는 것으로 보임 (5, 미정 1) |
| 반려 | 서명자 거절 → 요청 `DECLINED`로 즉시 종료 | 대체로 일치 (5) |
| 회수 | "취소"(진행 중이면 가능). 기한은 확인하지 않음 | 서명 요청 기간 안에만 (6) |
| 수정 후 재발송 | 없음. "메일 재발송"은 같은 문서의 링크를 다시 보내는 기능 | 회수·반려 문서의 데이터를 고쳐 재발송하는 API (7) |
| 참조자 | 완료 시 링크 메일 → 인증번호 → 내려받기 | 서명이 끝난 문서를 메일로 받음 (3, 미정 7) |
