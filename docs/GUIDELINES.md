# 업무 지침

- 버전: v2 (2026-11-23)
  - v1: 지침 1~8
  - v2: 미정 사항 1~5에 대한 결정 반영 (지침 9~13)
- **이 문서가 현재 구현보다 우선합니다.** 구현이 지침과 다르면 지침에 맞춰 고칩니다.
- **수정 규칙**: 사용자가 지침 업데이트를 지시하거나 미정 사항에 답했을 때만 고칩니다. 지침에 없는 내용을 임의로 정하지 않습니다. 해석이 필요하면 아래 "미정 사항"에 적고 사용자에게 묻습니다.

## 용어

| 용어 | 뜻 |
|---|---|
| 요청자 | 서비스에 로그인해 템플릿을 만들고, API로 서명을 요청하는 사람 |
| 서명자 | 서명 요청을 받아 문서에 서명하는 사람 (계정 없음) |
| 참조자 | 서명이 모두 끝난 문서만 받는 사람 |
| 템플릿 | 서명 요청에 쓰는 문서 양식. 요청자가 웹에서 만들고 편집한다 |
| 문서 | 템플릿으로 만든 서명 요청 한 건 |
| 종료처리 | 문서가 더 이상 진행되지 않는 상태가 되는 것 (반려, 회수 등) |

## 지침

### 1. 요청자 웹 화면
요청자가 웹 페이지에서 할 수 있는 일은 다음뿐입니다.
- 보낸 문서 관리
- 템플릿 관리, 템플릿 생성·편집
- API 토큰 관리

### 2. 서명자 웹 화면
서명자는 웹 페이지에서 **전달받은 문서의 서명 진행만** 할 수 있습니다.

### 3. 참조자
참조자는 **서명이 끝난 뒤 문서만 메일로** 전달받습니다. 전달 방식은 지침 12를 따릅니다.

### 4. 서명 요청은 API로만
- 서명 요청은 **API 호출로만** 합니다. 웹 화면에서는 서명을 요청하지 않습니다.
- 요청 JSON에 **템플릿 번호**를 넣고, 해당 템플릿으로 서명을 요청합니다.

### 5. 반려
- 서명자는 받은 문서를 반려할 수 있습니다.
- 반려된 문서는 **후순위 서명자와 관계없이 즉시 종료처리**됩니다.

### 6. 회수
- 요청자는 **종료처리되지 않은 문서**를 **서명 요청 기간 안에** 회수할 수 있습니다.
- 회수된 문서는 종료처리됩니다.

### 7. 수정 후 재발송 API
회수되거나 반려된 문서의 **데이터를 수정해서 재발송하는 API**를 구현해야 합니다. 재발송 결과는 지침 13을 따릅니다.

### 8. 그 밖의 사항
그 밖의 사항은 이후 결정하며, 사용자가 지침 업데이트를 지시할 때 이 문서에 반영합니다.

### 9. 서명 순서 (템플릿 설정)
- 템플릿을 설정할 때 **순차 / 비순차**를 옵션으로 고를 수 있습니다.
  - 순차: 정해진 순서대로 서명자에게 차례로 진행
  - 비순차: 서명자들이 순서와 관계없이 진행

### 10. 템플릿 구성 요소
템플릿에는 다음을 넣을 수 있습니다.
- 대상 PDF
- 서명 입력칸
- 워터마크
- 텍스트 박스
- 체크박스
- 첨부파일

### 11. 요청 JSON
- 서명 요청 JSON 안에 **이메일 등 수신자 정보**를 넣어 발송합니다.
- **주소록 등록 기능**은 검토가 필요합니다 (아직 구현 대상 아님).

### 12. 완료 문서 전달
완료된 문서는 **다운로드 링크를 메일로** 보냅니다.

### 13. 재발송은 새 문서
- 수정 후 재발송하면 **새 문서를 만듭니다.**
- 새 문서와 원래 문서(회수·반려된 문서)는 **감사 추적에서 서로 연결**합니다.

## 미정 사항 (결정 전에는 임의로 구현하지 않고 사용자에게 확인)

### 처음부터 남아 있던 것
1. **템플릿 번호 형식**: 숫자 번호인지, 다른 식별자인지.
2. **요청 데이터 범위**: 지침 7의 "수정할 데이터"가 무엇인지 (수신자 정보, 기간, 텍스트 박스 같은 칸에 미리 채우는 값 등).
3. **서명 요청 기간**: 요청할 때 API로 정하는지, 템플릿 기본값이 있는지, 최대 기간이 있는지.
4. **보낸 문서 관리 범위**: 웹에서 할 수 있는 동작 (조회, 회수, 완료본 내려받기 등). 회수를 웹에서도 하는지, API로만 하는지.
5. **서명자 본인 확인**: 지금처럼 메일 링크 + 이메일 인증번호를 유지하는지.

### v2 결정에서 새로 생긴 것
6. **첨부파일의 뜻**: 서명자가 파일을 올리는 칸(예: 신분증 사본 제출)인지, 요청자가 문서에 덧붙여 보내는 참고 파일인지. 서명자가 올리는 경우 허용 형식과 크기, 완료 문서에 어떻게 포함하는지.
7. **워터마크**: 템플릿 단위로 문구나 이미지를 정하는지, 진행 중 화면에만 보이는지 완료 PDF에도 남는지.
8. **텍스트 박스**: 서명자가 입력하는 칸인지, 요청자가 요청 JSON으로 값을 채우는 칸인지, 둘 다인지.
9. **날짜 칸**: 지금 구현에 있는 날짜 칸이 지침 10 목록에 없습니다. 빼는지, 텍스트 박스로 대신하는지.
10. **수신자와 칸 연결**: 템플릿의 칸을 어떤 서명자가 채우는지 템플릿에서 정하는 방식 (예: "서명자 1", "서명자 2" 같은 자리를 두고 요청 JSON에서 자리마다 이메일을 넣는 방식).
11. **완료 링크 받는 사람**: 참조자 외에 서명자, 요청자도 완료 문서 다운로드 링크 메일을 받는지. 링크를 열 때 인증번호 확인을 거치는지, 링크 유효 기간은 얼마인지.
12. **순차 진행 시 메일**: 순차일 때 다음 서명자에게는 앞 사람이 끝난 뒤에 메일이 가는지 (지금은 발송 시점에 모두에게 보냄).

## 참고: 지침과 현재 구현의 차이 (2026-11-23 기준, 지침 아님)

| 항목 | 현재 구현 | 지침 |
|---|---|---|
| 서명 요청 | 웹에서 PDF 업로드 → 칸 배치 → 발송. API로도 같은 흐름 | API로만, 템플릿 번호 + 수신자 정보 JSON (4, 11) |
| 템플릿 | 없음. 요청마다 PDF와 칸을 새로 만듦 | 웹에서 템플릿 생성·편집·관리, 순차/비순차 설정 (1, 9) |
| 템플릿 구성 요소 | 텍스트, 날짜, 체크, 서명 칸 | 대상 PDF, 서명칸, 워터마크, 텍스트 박스, 체크박스, 첨부파일 (10). 워터마크·첨부파일 없음 |
| 요청자 웹 | 요청 작성, 편집, 발송까지 가능 | 보낸 문서 관리, 템플릿, API 토큰만 (1) |
| 서명 순서 | 모든 서명자가 동시에 진행 | 템플릿에서 순차/비순차 선택 (9) |
| 반려 | 서명자 거절 → 요청 `DECLINED`로 즉시 종료 | 대체로 일치 (5) |
| 회수 | "취소"(진행 중이면 가능). 기한은 확인하지 않음 | 서명 요청 기간 안에만 (6) |
| 수정 후 재발송 | 없음. "메일 재발송"은 같은 문서의 링크를 다시 보내는 기능 | 새 문서를 만들고 감사 추적에서 원래 문서와 연결 (7, 13) |
| 완료 문서 전달 | 완료 시 링크 메일 → 인증번호 → 내려받기 | 다운로드 링크를 메일로 (3, 12). 대체로 일치, 인증번호 여부는 미정 11 |
| 주소록 | 없음 | 검토 필요, 아직 구현 대상 아님 (11) |
