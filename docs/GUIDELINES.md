## 용어

| 용어 | 뜻 |
|---|---|
| 요청자 | 서비스에 로그인해 템플릿을 만들고, API로 서명을 요청하는 사람 |
| 서명자 | 서명 요청을 받아 문서에 서명하는 사람 (계정 없음) |
| 참조자 | 서명이 모두 끝난 문서만 받는 사람 |
| 템플릿 | 서명 요청에 쓰는 문서 양식. 요청자가 웹에서 만들고 편집한다 |
| 문서 | 템플릿으로 만든 서명 요청 한 건 |
| 수신자 자리 | 템플릿에 정해 두는 "서명자 1", "서명자 2" 같은 자리. 요청할 때 자리마다 실제 사람을 넣는다 |
| 종료처리 | 문서가 더 이상 진행되지 않는 상태가 되는 것 (반려, 회수 등) |

## 지침

### 1. 요청자 웹 화면
요청자가 웹 페이지에서 할 수 있는 일은 다음뿐입니다.
- 보낸 문서 관리 (지침 19)
- 템플릿 관리, 템플릿 생성·편집
- API 토큰 관리

### 2. 서명자 웹 화면
서명자는 웹 페이지에서 **전달받은 문서의 서명 진행만** 할 수 있습니다.

### 3. 참조자
참조자는 **서명이 끝난 뒤 문서만 메일로** 전달받습니다. 전달 방식은 지침 12를 따릅니다.

### 4. 서명 요청은 API로만
- 서명 요청은 **API 호출로만** 합니다. 웹 화면에서는 새 서명을 요청하지 않습니다.
- 요청 JSON에 **템플릿 번호**를 넣고, 해당 템플릿으로 서명을 요청합니다.
- 예외: 회수·반려된 문서의 수정 후 재발송은 웹에서도 할 수 있습니다. 이때 웹은 같은 재발송 API를 씁니다 (지침 20).

### 5. 반려
- 서명자는 받은 문서를 반려할 수 있습니다.
- 반려된 문서는 **후순위 서명자와 관계없이 즉시 종료처리**됩니다.

### 6. 회수
- 요청자는 **종료처리되지 않은 문서**를 **서명 요청 기간 안에** 회수할 수 있습니다.
- 회수된 문서는 종료처리됩니다.
- 회수는 **API와 웹 모두** 할 수 있습니다. 웹은 같은 회수 API를 씁니다.

### 7. 수정 후 재발송 API
회수되거나 반려된 문서의 **데이터를 수정해서 재발송하는 API**를 구현해야 합니다. 설계는 지침 20, 결과는 지침 13을 따릅니다.

### 8. 그 밖의 사항
그 밖의 사항은 이후 결정하며, 사용자가 지침 업데이트를 지시할 때 이 문서에 반영합니다.

### 9. 서명 순서 (템플릿 설정)
- 템플릿을 설정할 때 **순차 / 비순차**를 옵션으로 고를 수 있습니다.
  - 순차: 정해진 순서대로 서명자에게 차례로 진행합니다. **앞 서명자가 끝나야 다음 서명자에게 요청이 갑니다** (메일 포함).
  - 비순차: 서명자들이 순서와 관계없이 진행합니다. **발송할 때 모든 서명자에게 한 번에 메일을 보냅니다.**

### 10. 템플릿 구성 요소
템플릿에는 다음을 넣을 수 있습니다.

| 요소 | 내용 |
|---|---|
| 대상 PDF | 서명받을 원본 문서 |
| 서명 입력칸 | 서명자가 서명하는 칸 |
| 날짜 칸 | 날짜를 넣는 칸 |
| 텍스트 박스 | 두 가지 방식이 있습니다 (지침 14) |
| 체크박스 | 체크 칸 |
| 워터마크 | 문구 또는 이미지. 완료 PDF에도 남습니다 (지침 15) |
| 첨부파일 | 두 가지 옵션이 있습니다 (지침 16) |

### 11. 요청 JSON과 수신자 자리
- 템플릿에는 "서명자 1", "서명자 2" 같은 **수신자 자리**를 두고, 칸마다 어느 자리가 채울지 정합니다.
- 서명 요청 JSON에는 **템플릿 번호**와 **자리마다 들어갈 사람의 이메일 등 정보**를 넣어 발송합니다.
- **주소록 등록 기능**은 검토가 필요합니다 (아직 구현 대상 아님).

### 12. 완료 문서 전달
- 완료된 문서는 **다운로드 링크를 메일로** 보냅니다.
- 받는 사람: **참조자, 서명자, 요청자** 모두.
- 링크를 열려면 **인증번호 확인이 필요**합니다 (지침 18의 이메일 인증).
- 링크는 **완료 후 30일** 동안 열 수 있습니다 (현행 유지).
- 요청자는 이와 별개로 **웹에서 바로** 내려받을 수 있습니다 (지침 19).

### 13. 재발송은 새 문서
- 수정 후 재발송하면 **새 문서를 만듭니다.**
- 새 문서는 원래 문서(회수·반려된 문서)와 **이력이 이어지는 별도 문서**로 봅니다. 두 문서는 감사 추적에서 서로 연결합니다.
- 재발송할 때 **템플릿 번호도 바꿀 수 있습니다.** 그 밖의 데이터는 새 요청과 같은 형식으로 받습니다.

### 14. 텍스트 박스
텍스트 박스는 두 방식 모두 지원합니다.
- **서명자 입력**: 서명자가 서명할 때 채웁니다.
- **요청자 입력**: 요청자가 **템플릿에서 값을 채워 둡니다.** 서명자는 고칠 수 없습니다.

### 15. 워터마크
- **문구와 이미지 모두** 쓸 수 있습니다.
- **모든 페이지에 같은 좌표, 같은 크기**로 들어갑니다.
- **좌표, 투명도, 기울기, 크기** 등은 **템플릿을 만들 때** 정합니다.
- 서명 진행 화면뿐 아니라 **완료 PDF에도 남습니다.**

### 16. 첨부파일
- 첨부파일은 **두 가지를 별도 옵션**으로 둡니다.
  - **요청자 첨부**: 요청자가 문서와 함께 보내는 파일
  - **서명자 첨부**: 서명자가 올리는 파일. **요청자만 볼 수 있게** 권한을 처리합니다. 다른 서명자와 참조자는 볼 수 없습니다.
- 제한 (서명자 첨부, 요청자 첨부 모두 같게 적용)
  - 개수: **최대 5개**
  - 크기: **전체 합계 10MB**
  - 형식: **문서·사진** — PDF, DOC/DOCX, XLS/XLSX, PPT/PPTX, HWP, JPG, PNG (Claude 제안, 사용자 승인)
- **서명자 첨부는 완료 PDF에 넣지 않습니다.** 완료 PDF는 다른 참여자도 받기 때문입니다. 요청자는 웹에서 따로 내려받습니다 (지침 19).

### 17. 서명 요청 기간
- 기본값은 **2주**, 최대 **한 달**입니다.

### 18. 서명자 본인 확인
- 지금은 **이메일 인증번호**만 씁니다.

### 19. 보낸 문서 관리 (요청자 웹)
| 기능 | 내용 |
|---|---|
| 목록 | 상태별 필터, 제목·수신자 이메일 검색, 기간별 조회 모두 지원 |
| 상세 | 서명자별 진행 상태와 감사 추적을 모두 보여 줌. 재발송으로 이어진 문서도 함께 표시 |
| 회수 | 웹에서도 가능 (웹은 회수 API를 씀) |
| 수정 후 재발송 | 웹에서도 가능 (지침 20) |
| 완료 문서 | 요청자는 웹에서 바로 내려받음 |
| 서명자 첨부파일 | 요청자는 웹에서 바로 내려받음 |
| 요청 메일 다시 보내기 | 진행 중인 서명자에게 요청 메일을 다시 보냄. **웹에만** 두고 API로는 제공하지 않음 |
| 삭제 | 지침 22 |

### 20. 문서 조회 API와 재발송 (Claude 제안, 사용자 위임으로 결정)
- **조회 API**는 문서 상세를 돌려주면서 `resend` 항목을 함께 줍니다.
  - `available`: 지금 재발송할 수 있는지 (회수·반려된 문서만 `true`)
  - `request`: 새 서명 요청 JSON과 **같은 형식**으로 채운 재발송용 데이터 (템플릿 번호, 수신자 자리별 정보, 기간 등)
- **재발송 API**는 원래 문서 번호를 받고, **바꿀 값만** 보내면 됩니다. 보내지 않은 값은 원래 문서에서 그대로 가져옵니다. 템플릿 번호도 바꿀 수 있습니다.
- 결과로 새 문서를 만들고, 원래 문서와 감사 추적에서 연결합니다 (지침 13).
- 웹에서는 회수·반려된 문서 상세 화면에 **"수정 후 재발송"** 버튼을 둡니다. 조회 API의 재발송용 데이터로 채운 양식을 열고, 저장하면 같은 재발송 API를 부릅니다.
- 이렇게 하면 API 사용자는 "조회 → 필요한 값만 수정 → 재발송"으로, 웹 사용자는 버튼 하나로 같은 일을 할 수 있습니다.

### 21. 서비스 범위
- 지금은 **개인 서비스**로 진행합니다. 문서와 템플릿은 만든 요청자 본인만 봅니다.
- 그룹(조직) 공유는 나중에 검토합니다.

### 22. 문서 삭제
- **종료된 문서만** 삭제할 수 있습니다. 진행 중인 문서는 삭제할 수 없습니다.
- 삭제는 **목록에서만 숨깁니다.** 파일, 데이터, 감사 추적은 지우지 않습니다.
- **재발송으로 이어진 문서는 삭제할 수 없습니다** (원래 문서와 재발송한 새 문서 모두).

## 미정 사항 (결정 전에는 임의로 구현하지 않고 사용자에게 확인)

1. **템플릿 번호 형식**: 검토 필요 (사용자 답변). 숫자 번호인지, 다른 식별자인지.
2. **보관 기간**: 따로 정하지 않음 (사용자 답변: 아직 생각 안 해 봄).
3. **"종료된 문서"의 범위 (지침 22)**: 용어 정의상 반려·회수뿐 아니라 **완료와 만료(기간 초과)** 도 포함하는 것으로 적었습니다. 완료된 문서도 삭제(숨기기)할 수 있는 것이 맞는지 확인이 필요합니다.
4. **숨긴 문서 다시 보기**: 숨긴 문서를 다시 볼 수 있는 화면(예: "숨긴 문서 보기" 필터)이 필요한지.
