# 업무 지침

- 버전: v3 (2026-11-23)
  - v1: 지침 1~8
  - v2: 서명 순서, 템플릿 구성, 요청 JSON, 완료 전달, 재발송 (지침 9~13)
  - v3: 첨부파일, 워터마크, 텍스트 박스, 날짜 칸, 수신자 자리, 완료 링크, 순차 메일, 재발송 문서, 기간, 본인 확인 (지침 9~17 보완·추가)
- **이 문서가 현재 구현보다 우선합니다.** 구현이 지침과 다르면 지침에 맞춰 고칩니다.
- **수정 규칙**: 사용자가 지침 업데이트를 지시하거나 미정 사항에 답했을 때만 고칩니다. 지침에 없는 내용을 임의로 정하지 않습니다. 해석이 필요하면 아래 "미정 사항"에 적고 사용자에게 묻습니다.

## 용어

| 용어 | 뜻 |
|---|---|
| 요청자 | 서비스에 로그인해 템플릿을 만들고, API로 서명을 요청하는 사람 |
| 서명자 | 서명 요청을 받아 문서에 서명하는 사람 (계정 없음) |
| 참조자 | 서명이 모두 끝난 문서만 받는 사람 |
| 템플릿 | 서명 요청에 쓰는 문서 양식. 요청자가 웹에서 만들고 편집한다 |
| 문서 | 템플릿으로 만든 서명 요청 한 건 |
| 수신자 자리 | 템플릿에 정해 두는 "서명자 1", "서명자 2" 같은 자리. 요청할 때 자리마다 실제 사람을 넣는다 |
| 종료처리 | 문서가 더 이상 진행되지 않는 상태가 되는 것 (반려, 회수 등) |

## 지침

### 1. 요청자 웹 화면
요청자가 웹 페이지에서 할 수 있는 일은 다음뿐입니다.
- 보낸 문서 관리 (구체 범위는 미정 사항 A)
- 템플릿 관리, 템플릿 생성·편집
- API 토큰 관리

### 2. 서명자 웹 화면
서명자는 웹 페이지에서 **전달받은 문서의 서명 진행만** 할 수 있습니다.

### 3. 참조자
참조자는 **서명이 끝난 뒤 문서만 메일로** 전달받습니다. 전달 방식은 지침 12를 따릅니다.

### 4. 서명 요청은 API로만
- 서명 요청은 **API 호출로만** 합니다. 웹 화면에서는 서명을 요청하지 않습니다.
- 요청 JSON에 **템플릿 번호**를 넣고, 해당 템플릿으로 서명을 요청합니다.

### 5. 반려
- 서명자는 받은 문서를 반려할 수 있습니다.
- 반려된 문서는 **후순위 서명자와 관계없이 즉시 종료처리**됩니다.

### 6. 회수
- 요청자는 **종료처리되지 않은 문서**를 **서명 요청 기간 안에** 회수할 수 있습니다.
- 회수된 문서는 종료처리됩니다.

### 7. 수정 후 재발송 API
회수되거나 반려된 문서의 **데이터를 수정해서 재발송하는 API**를 구현해야 합니다. 재발송 결과는 지침 13을 따릅니다.

### 8. 그 밖의 사항
그 밖의 사항은 이후 결정하며, 사용자가 지침 업데이트를 지시할 때 이 문서에 반영합니다.

### 9. 서명 순서 (템플릿 설정)
- 템플릿을 설정할 때 **순차 / 비순차**를 옵션으로 고를 수 있습니다.
  - 순차: 정해진 순서대로 서명자에게 차례로 진행합니다. **앞 서명자가 끝나야 다음 서명자에게 요청이 갑니다** (메일 포함).
  - 비순차: 서명자들이 순서와 관계없이 진행합니다.

### 10. 템플릿 구성 요소
템플릿에는 다음을 넣을 수 있습니다.

| 요소 | 내용 |
|---|---|
| 대상 PDF | 서명받을 원본 문서 |
| 서명 입력칸 | 서명자가 서명하는 칸 |
| 날짜 칸 | 날짜를 넣는 칸 |
| 텍스트 박스 | 두 가지 방식이 있습니다 (지침 14) |
| 체크박스 | 체크 칸 |
| 워터마크 | 완료 PDF에도 남습니다 (지침 15) |
| 첨부파일 | 두 가지 옵션이 있습니다 (지침 16) |

### 11. 요청 JSON과 수신자 자리
- 템플릿에는 "서명자 1", "서명자 2" 같은 **수신자 자리**를 두고, 칸마다 어느 자리가 채울지 정합니다.
- 서명 요청 JSON에는 **템플릿 번호**와 **자리마다 들어갈 사람의 이메일 등 정보**를 넣어 발송합니다.
- **주소록 등록 기능**은 검토가 필요합니다 (아직 구현 대상 아님).

### 12. 완료 문서 전달
- 완료된 문서는 **다운로드 링크를 메일로** 보냅니다.
- 받는 사람: **참조자, 서명자, 요청자** 모두.
- 링크를 열려면 **인증번호 확인이 필요**합니다 (지침 18의 이메일 인증).

### 13. 재발송은 새 문서
- 수정 후 재발송하면 **새 문서를 만듭니다.**
- 새 문서는 원래 문서(회수·반려된 문서)와 **이력이 이어지는 별도 문서**로 봅니다. 두 문서는 감사 추적에서 서로 연결합니다.

### 14. 텍스트 박스
텍스트 박스는 두 방식 모두 지원합니다.
- **서명자 입력**: 서명자가 서명할 때 채웁니다.
- **요청자 입력**: 요청자가 **템플릿에서 값을 채워 둡니다.** 서명자는 고칠 수 없습니다.

### 15. 워터마크
워터마크는 서명 진행 화면뿐 아니라 **완료 PDF에도 남습니다.**

### 16. 첨부파일
첨부파일은 **두 가지를 별도 옵션**으로 둡니다.
- **요청자 첨부**: 요청자가 문서와 함께 보내는 파일
- **서명자 첨부**: 서명자가 올리는 파일. **요청자만 볼 수 있게** 권한을 처리합니다. 다른 서명자와 참조자는 볼 수 없습니다.

### 17. 서명 요청 기간
- 기본값은 **2주**, 최대 **한 달**입니다.

### 18. 서명자 본인 확인
- 지금은 **이메일 인증번호**만 씁니다.

## 미정 사항 (결정 전에는 임의로 구현하지 않고 사용자에게 확인)

### A. 보낸 문서 관리 범위 (지침 1)
요청자가 웹의 "보낸 문서 관리"에서 할 수 있는 일을 하나씩 정해 주세요.
1. **목록**: 상태별 필터, 제목·수신자 이메일 검색, 기간별 조회가 필요한가요?
2. **상세 보기**: 서명자별 진행 상태와 감사 추적(재발송으로 이어진 문서 포함)을 보여 주나요?
3. **회수**: 웹에서도 회수할 수 있나요, API로만 하나요?
4. **수정 후 재발송**: API로만 하나요, 웹에서도 하나요? (지침 4는 서명 요청을 API로만 하도록 정함)
5. **완료 문서 내려받기**: 웹에서 바로 내려받을 수 있나요?
6. **서명자 첨부파일 보기**: 웹에서 내려받을 수 있나요?
7. **알림 다시 보내기**: 진행 중인 서명자에게 요청 메일을 다시 보내는 기능을 웹에 두나요? (지금 구현에 있음)
8. **삭제·보관**: 문서를 삭제하거나 숨길 수 있나요? 보관 기간이 있나요?
9. **공유 범위**: 문서는 요청한 본인만 보나요, 같은 조직의 다른 요청자도 볼 수 있나요?

### B. 그 밖에 남은 것
1. **템플릿 번호 형식**: 검토 필요 (사용자 답변). 숫자 번호인지, 다른 식별자인지.
2. **재발송 데이터 범위**: 재발송은 "이력이 이어지는 별도 문서"로 본다고 정함(지침 13). 새 문서이므로 새 요청과 같은 형식(수신자 정보, 기간 등)을 받는 것으로 이해했는데, 맞는지. 템플릿 번호를 바꿀 수 있는지.
3. **첨부파일 세부**: 허용 형식과 크기, 개수. 서명자 첨부는 요청자만 볼 수 있으므로 완료 PDF(다른 참여자도 받는 파일)에는 넣지 않는 것으로 이해했는데, 맞는지. 요청자 첨부는 서명자·참조자에게 어떻게 보이는지.
4. **워터마크 세부**: 문구인지 이미지인지, 위치·투명도를 템플릿에서 정하는지.
5. **완료 링크 유효 기간**: 얼마 동안 열 수 있는지 (지금 구현은 완료 후 30일).
6. **비순차일 때 메일**: 비순차면 발송 시점에 모든 서명자에게 한 번에 보내는 것이 맞는지.

## 참고: 지침과 현재 구현의 차이 (2026-11-23 기준, 지침 아님)

| 항목 | 현재 구현 | 지침 |
|---|---|---|
| 서명 요청 | 웹에서 PDF 업로드 → 칸 배치 → 발송. API로도 같은 흐름 | API로만, 템플릿 번호 + 자리별 수신자 정보 JSON (4, 11) |
| 템플릿 | 없음. 요청마다 PDF와 칸을 새로 만듦 | 웹에서 템플릿 생성·편집·관리, 순차/비순차, 수신자 자리 (1, 9, 11) |
| 템플릿 구성 요소 | 텍스트, 날짜, 체크, 서명 칸 | + 요청자 입력 텍스트 박스, 워터마크, 요청자·서명자 첨부 (10, 14~16) |
| 요청자 웹 | 요청 작성, 편집, 발송까지 가능 | 보낸 문서 관리, 템플릿, API 토큰만 (1) |
| 서명 순서 | 모든 서명자에게 동시에 메일, 동시 진행 | 템플릿에서 순차/비순차. 순차면 앞 사람이 끝난 뒤 다음 사람에게 메일 (9) |
| 반려 | 서명자 거절 → 요청 `DECLINED`로 즉시 종료 | 대체로 일치 (5) |
| 회수 | "취소"(진행 중이면 가능). 기한은 확인하지 않음 | 서명 요청 기간 안에만 (6) |
| 요청 기간 | 선택, 최대 90일 | 기본 2주, 최대 한 달 (17) |
| 수정 후 재발송 | 없음. "메일 재발송"은 같은 문서의 링크를 다시 보내는 기능 | 이력이 이어지는 새 문서, 감사 추적에서 연결 (7, 13) |
| 완료 문서 전달 | 모든 수신자와 요청자에게 메일. 수신자는 링크 → 인증번호 → 내려받기, 요청자는 로그인 후 내려받기 | 참조자·서명자·요청자 모두 링크 메일, 인증번호 필요 (12). 요청자도 인증번호 링크로 받는지 구현 시 확인 |
| 본인 확인 | 이메일 인증번호 | 일치 (18) |
| 주소록 | 없음 | 검토 필요, 아직 구현 대상 아님 (11) |
